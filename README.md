# TapToGo

NFC-карточки и QR-стикеры, которые ведут гостей бизнеса на страницу отзывов в 2ГИС, плюс кабинет со статистикой для владельца и админ-панель для команды платформы.

По умолчанию приложение работает на моковых данных: все страницы, роли, формы, графики и правила работают без внешних сервисов. База и вход на Supabase уже написаны и включаются переменной `DATA_SOURCE=supabase` (см. [docs/SUPABASE_MIGRATION.md](docs/SUPABASE_MIGRATION.md)); почта (Resend) не используется, а 2ГИС API временно скрыт.

## Запуск

```bash
pnpm install && pnpm dev
```

В Windows PowerShell 5.1 оператора `&&` нет. Используйте `;` (`pnpm install; pnpm dev`) или PowerShell 7 (`pwsh`).

Откройте http://localhost:3000. Файл `.env.local` не нужен: для разработки у всех переменных есть значения по умолчанию (см. `.env.example`).

Нужная версия Node.js (24.x) закреплена в `package.json` (`devEngines.runtime`): pnpm сам скачает её при `pnpm install`.

## Разделы

- `/`: лендинг с тарифами и формой заявки (заявки появляются в `/admin/leads`)
- `/app`: кабинет клиента — дашборд, карточки, филиалы, сотрудники, отчёты, команда, настройки, поддержка

## Что замокано

Таблица описывает режим `DATA_SOURCE=mock`. В режиме `supabase` база, вход и очередь писем настоящие (колонка «Потом» уже реализована), а 2ГИС и Redis по-прежнему не подключены.

| Что                   | Сейчас                                                                                              | Потом                               |
| --------------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------- |
| База данных           | в памяти процесса, заполняется из `src/mocks/seed.ts` при старте; изменения живут до перезапуска    | Supabase Postgres + RLS             |
| Вход и сессии         | `MockAuthService`: пароль `demo12345`, подписанная cookie                                           | Supabase Auth                       |
| Письма                | не отправляются: администратор отправляет их вручную из раздела «Ручная отправка» (`/admin/outbox`) | Resend, если понадобится автоматика |
| Рейтинг и отзывы 2ГИС | `MockReviewsProvider` на демо-снапшотах; ручная синхронизация работает                              | 2ГИС API + ежедневный cron          |
| Лимиты частоты        | в памяти одного процесса                                                                            | Redis, когда серверов > 1           |
| Оплата                | платежи вносит сотрудник вручную                                                                    | не планировалось в ТЗ               |

Демо-данные детерминированные: при каждом запуске одни и те же 3 организации, 6 филиалов, 36 карточек, 10 сотрудников и 90 дней касаний.

## Редирект с карточки

`/t/{code}`: ссылка, которая записывается на NFC-метку (`?s=q` для QR-кода).

- Если карточка активна, сервер сразу отвечает `302` на сохранённую проверенную цель. Касание записывается уже после ответа.
- Для неактивированной, приостановленной или потерянной карточки показывается нейтральная страница без данных клиента. Для неизвестного кода — 404.
- Лимит: 60 запросов в минуту с одного IP. IP берётся из `X-Real-IP` или последнего значения `X-Forwarded-For`, поэтому reverse proxy перед приложением **обязан** перезаписывать `X-Real-IP`.
- Дубли и уникальные посетители считаются по cookie `ttg_seen` на телефоне гостя. В ней только коды карточек и время последнего касания, без идентификатора человека. Перед запуском нужно добавить уведомление о cookie.

## Демо-аккаунты

Пароль у всех: `demo12345`. В режиме разработки на странице `/login` есть кнопки «Войти как…».

| Роль    | Email                    | Куда попадает                                   |
| ------- | ------------------------ | ----------------------------------------------- |
| ADMIN   | `admin@taptogo.kz`       | `/admin`, всё                                   |
| ADMIN   | `admin2@taptogo.kz`      | второй администратор (не в списке «Войти как…») |
| OWNER   | `owner@coffeepoint.kz`   | `/app`: Coffee Point + AquaDrive                |
| MANAGER | `manager@coffeepoint.kz` | `/app`: Coffee Point                            |

Ролей всего три. Администратор платформы один тип: команда небольшая, поэтому разделения на суперадмина и поддержку нет. Обращения клиентов приходят администраторам в раздел «Обращения». Клиент — владелец (всё, включая команду и данные организации) или менеджер (карточки и сотрудники).

## Страницы для разработки

Только в dev-режиме. В production-сборке они отвечают 404.

- `/dev/data`: что сгенерировал seed (организации, подписки, коды карточек).

Ссылки приглашений и сброса пароля строятся от `APP_URL` (по умолчанию `http://localhost:3000`). Очередь хранится в памяти процесса: после перезапуска сервера неотправленные сообщения теряются.

## Перед запуском в production

- Уведомление о cookie и текст согласия на обработку персональных данных в форме заявки.
- Реальные контакты в `src/config/contacts.ts` (сейчас заглушки).
- Окончательный `APP_URL`: от него строятся ссылки на NFC-метках, после печати карточек домен менять нельзя.
- Остальное — чек-лист в конце [docs/SUPABASE_MIGRATION.md](docs/SUPABASE_MIGRATION.md).
